# Module: `cpu6502.py`

`cpu6502.py` is the instruction-level NMOS 6502/6510 core used by SID2MIDI to run real SID init/play routines. It is callback-based: the CPU asks the host for memory reads and writes, and the host decides whether an address maps to RAM, ROM, SID, CIA, VIC or the 6510 processor port.

## Main responsibility

The CPU module exists to execute enough of the original C64 player code to expose SID register writes. It is not a PHI2/transistor-level C64 emulator. Its target is stable SID-register extraction.

## Important parts

### `CPU6502(read, write, ...)`

Creates the CPU and binds memory callbacks.

Important constructor options:

- `strict_jam`: raise on KIL/JAM instead of stopping safely.
- `strict_unstable`: raise on unstable NMOS opcodes such as ANE/LXA/AHX family.
- `trace`: enable instruction tracing.
- `trace_limit`: rolling trace size. `None` means unbounded, `0` means counter-only.
- `decimal_flags`: decimal-mode policy: `nmos`, `binary`, `adjusted`, or `strict`.
- `intercept_6510_port`: let CPU trap `$0000/$0001` internally.
- `mirror_6510_port_writes` / `mirror_6510_port_reads`: allow host logging or side effects while keeping CPU-owned port state authoritative.

### Opcode execution

`step()` executes one instruction, updates diagnostics, handles page-cross cycle additions, and returns `False` if execution has stopped or jammed.

Diagnostics include:

- `last_pc`
- `last_opcode`
- `opcode_count`
- `illegal_opcode_count`
- `unstable_opcode_count`
- `jam_count`
- `brk_count`
- `last_stop_reason`
- `last_instruction_count`

### High-level calls

- `call(addr, a=0, x=0, y=0, max_ins=...)` runs a SID init/play subroutine until the sentinel return address.
- `irq(vec=0xFFFE, ...)` simulates an IRQ entry.
- `nmi(vec=0xFFFA, ...)` simulates an NMI entry.

### 6510 processor port

The C64 uses CPU addresses `$0000/$0001` to control memory banking. The core stores:

- `port_dir`
- `port_data`
- `effective_6510_port()`

The effective value is what the C64 host uses to decide whether BASIC, KERNAL, CHARGEN or I/O is visible.

### Trace model

The trace model is intentionally explicit:

- `trace_seen`: all traced instructions seen since last clear.
- `trace_total`: retained trace rows currently in the buffer.
- `trace_dropped`: `trace_seen - trace_total`.
- `trace_snapshot()`: list copy of retained rows.
- `clear_trace()`: resets trace buffer and counters.

## Accuracy boundary

Implemented well for SID extraction:

- all official NMOS 6502 opcodes covered;
- common undocumented opcodes used by C64 players/decrunchers;
- safe KIL/JAM behavior;
- IRQ/NMI/BRK diagnostics;
- decimal-mode policy framework.

Not claimed:

- PHI2 bus-exact execution;
- RDY/SYNC pin behavior;
- VIC badline/sprite DMA interference;
- transistor-accurate invalid-BCD edge cases.
